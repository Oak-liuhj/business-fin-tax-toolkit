# 内部审计

## 何时触发

用户要做年度内审、专项审计、内控评价、SOX 合规，或问"该怎么查""怎么抽样""这个发现算什么级别"。

## 需要什么输入

**必需**：审计对象与范围（哪个循环、哪个期间、哪家主体）、审计目标（合规/舞弊/效率/报表可靠性）。
**程序性输入**：流程图或制度文件、系统导出数据（凭证、付款、合同、工资、账户）。
**可选**：上年度审计发现与整改情况、外部审计意见。

## 工作步骤

> 六大循环的标准程序清单、关键控制点与 SOX 404 三层测试要点见 `references/audit-programs-sox.md`，本章只写怎么用。

### 第一步：审计计划
```
1. 范围与期间
2. 目标与依据（内控制度 / SOX 404 / 集团要求）
3. 风险评估：固有风险 × 控制风险，定高/中/低
4. 程序清单与时间表
5. 人员与分工
6. 交付物（底稿、发现报告、整改跟踪表）
```

### 第二步：了解与穿行测试
每个循环选 1–2 笔完整业务从头走到尾，画清"谁在什么节点做什么审批"，确认制度写的和实际做的是否一致。**穿行测试发现的差异往往就是控制缺陷**。

### 第三步：控制测试（抽样）

| 控制频率 | 年度发生次数 | 建议样本量 |
|---|---|---|
| 高频（日/每笔） | >250 | 25 |
| 高频 | 50–250 | 15 |
| 中频 | <50 | 5–10 或全查 |
| 月度 | 12 | 2–3 |
| 季度 | 4 | 2 |
| 年度 | 1 | 1 |

抽样 = 随机抽样 + 重点项（大额、异常、关联方、期末）结合，禁止"只挑好查的"。

### 第四步：实质性测试与数据分析
优先全量分析替代抽样。必做清单：

- 供应商/客户主数据与员工信息碰撞（同地址、同电话、同银行账户）
- 重复付款（同供应商 + 同金额 + 时间窗）
- 无订单付款、付款账户与合同不一致
- 期末前后 5 天的大额交易（cut-off）
- 应收账款账龄与回款率，超期客户单项评估
- 存货呆滞与单位成本环比异常
- 工资表 vs 花名册 vs 社保 vs 个税四方比对，离职人员工资延续
- 银行账户完整性 + 余额调节表未达账项 >30 天
- 在建工程长期不转固、利息资本化复核

**每条线索都要写"可能的正常解释"**，避免误伤。

### 第五步：发现与分级

| 级别 | 判定标准 |
|---|---|
| 重大缺陷 | 可能导致报表重大错报且未被及时防止或发现 |
| 重要缺陷 | 低于重大但足以引起审计委员会关注 |
| 一般缺陷 | 其他 |

**定级前先看补偿性控制**是否存在且有效。缺陷描述只写事实，不写推测。

### 第六步：SOX 404 适配（如适用）
- 公司层面控制（ELC）：治理、道德合规、风险评估、集中处理
- 业务流程控制：六循环 + ITAC
- ITGC：访问管理（离职 3 日内停用？特权账号清单与日志）、变更管理（审批/测试/回滚）、运维（备份恢复演练）、程序开发

### 第七步：准则差异（如涉及 IFRS）
先确认报告目的与准则版本，不要默认套 CAS。关键差异：长期资产减值转回、开发支出资本化（IFRS 满足条件必须资本化）、关联方范围、持有待售、政府补助披露。

## 输出模板

```
一、审计概况（范围、期间、目标、方法、样本量）
二、总体结论（一句话）
三、控制矩阵
    控制目标 | 控制活动 | 责任人 | 频率 | 类型 | 测试结果 | 偏差
四、发现清单（逐条）
    4.1 事实描述
    4.2 影响（尽量量化）
    4.3 根本原因（流程/系统/人）
    4.4 风险评级 + 判定依据
    4.5 建议（可执行、有责任人、有期限）
五、管理层回复
六、整改跟踪表
七、附：数据分析异常清单与排除说明
```

## 自检清单

- [ ] 审计目标与范围写清楚，没有无限扩大
- [ ] 穿行测试做了，制度与实际差异已识别
- [ ] 样本量符合频率对应要求，抽样方法可追溯
- [ ] 数据分析覆盖了必做清单
- [ ] 每条线索都有"可能正常解释"
- [ ] 缺陷定级考虑了补偿性控制
- [ ] 发现只写事实，推测已标"待核实"
- [ ] 建议有责任人、期限、可验证的完成标准
- [ ] 涉及 IFRS 时确认过准则版本
## 证据与方法边界

数据异常必须能回指原文件/工作表/行号，导入工具为 `scripts/data_ingest.py`。样本量表仅为项目规划参考，需结合控制风险、总体、预期偏差和容忍偏差确定，不宣称固定样本量满足所有SOX项目。SOX是内控要求，与CAS/IFRS报告准则分开确认。
